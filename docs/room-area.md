# 談話室（下部領域）設計

## 概要

縦画面（portrait）時、4:3ゲームエリアの下に表示される装飾エリア。
前作の談話室を踏襲しつつ、最大3体の立ち絵配置とスロットタップ選択UIを導入する。

## 画面比率と表示モード

画面のアスペクト比に応じて3つのモードに分かれる。

| 画面比率 | モード | ゲームエリア配置 | 談話室 |
|---------|--------|---------------|-------|
| 4:3以上（横長） | 横画面モード | 画面中央 | 非表示 |
| 4:3〜2:3の間 | 縦画面（余白小） | **縦方向中央** | 非表示 |
| 2:3以下（縦長） | 縦画面（談話室あり） | 上部配置 | 表示 |

### 判定方法

- **談話室の表示**: `@media (max-aspect-ratio: 2/3)` で判定（CSSメディアクエリまたはTailwindカスタム）
- **ゲームエリアの縦中央配置**: 4:3〜2:3の間では `items-start` → `items-center` に切り替え
- **前作との違い**: 前作は `portrait`（1:1）をしきい値としていたが、今作は2:3に変更。iPadなど正方形に近いデバイスでは談話室を出さない

### 実装イメージ

```
横画面（4:3以上）:
┌────────────────────────────────────┐
│         4:3 ゲームエリア（中央）      │
└────────────────────────────────────┘

縦画面・余白小（4:3〜2:3）:
┌─────────────────────────┐
│          余白             │
│  ┌───────────────────┐  │
│  │ 4:3 ゲームエリア    │  │  ← 縦方向中央
│  └───────────────────┘  │
│          余白             │
└─────────────────────────┘

縦画面・談話室あり（2:3以下）:
┌─────────────────────────┐
│    4:3 ゲームエリア       │  height: 75dvw
│    (GameContainer)       │  背景は4:3内に収める
├─────────────────────────┤
│    談話室エリア            │  height: calc(100dvh - 75dvw)
│    (RoomArea)            │  width: 100dvw
└─────────────────────────┘
```

## 表示条件

- **談話室**: `@media (max-aspect-ratio: 2/3)` のときのみ表示
- 横画面・OBSブラウザソースでは非表示（4:3エリアのみ取り込まれる想定）
- ゲーム画面（4:3内）のアシスタントには影響しない（独立した領域）

### 上画面の背景画像の扱い

- 縦画面時、`body` の背景画像（寮別背景 `bg_*.png` 等）が4:3エリアの外にはみ出さないようにする
- 現状は `background-size: cover` で16:9の画像が画面全体に広がるため、4:3の下にも背景が見えてしまう
- 対策：縦画面時は背景画像を4:3エリア内に収める（`body` ではなく `GameContainer` の疑似要素に設定する等）
- 4:3エリアの外（談話室の背後）には `body` の `background-color` のみが見える形にし、その上に談話室の背景画像を重ねる

## 構成要素

### 1. 背景画像

- ユーザーが**寮を選択して背景を切り替え**できる（タレント選択とは独立）
- 切り替えUI：寮ボタン4つ（エンブレムまたはシンプルなボタン）を談話室エリア内に配置。タイトル画面のときのみ表示
- 背景画像一覧：`bg_wa.png`（バゥ寮）/ `bg_me.png`（ミュゥ寮）/ `bg_co.png`（クゥ寮）/ `bg_wh.png`（ウィニー寮）
- 選択した寮はLocalStorageに保存（`parermaster2_room` 内に含める）
- 初期値：ランダム
- 上画面（4:3ゲームエリア）の寮背景と被る場合がありうるが、一旦許容

### 2. テーブル（手前の遮蔽物）

- 談話室の手前にテーブル状の画像を配置し、タレントがテーブルの裏側に立っているように見せる
- テーブルで立ち絵の下半身を自然に隠すことで、クリップの不自然さを軽減
- **レイヤー順（奥→手前）**: 背景 → 立ち絵 → テーブル → 選択UI・吹き出し
- テーブル画像は要発注（`ui/room_table.png` 等）。横幅100%、高さは談話室エリアの下部30〜40%程度を想定

### 3. 立ち絵スロット（最大3体）

左・中央・右の3スロットに立ち絵を配置できる。

#### 配置

| スロット | クリック領域 | 画像表示位置 | 備考 |
|---------|------------|------------|------|
| 左 | 0〜33% | スロット中央 | — |
| 中央 | 33〜66% | スロット中央 | 初期状態ではここに1体（前作同様） |
| 右 | 66〜100% | スロット中央 | — |

- 立ち絵画像：1期生 `kv/orig/{student_id}.png`（833×1500px）、2期生 `kv/orig/{student_id}.webp`（1200×1586〜1963px、高さは個体差あり）
- GSAPアニメーション：前作踏襲（上下移動・左右移動・回転・拡大縮小を各スロット独立で実行）
- 重なり順：左が最背面、中央が中間、右が最前面（z-index制御）

#### 立ち絵のサイズ・縦位置（顔サイズ基準モデル）

サイズと縦位置は、KV画像の**実測値**と**タレントの身長**から算出する。実装は `kvMetrics.ts`（実測値）と `kvScaleStyle.ts`（計算式）。

**基準単位 U（＝表示上の頭サイズ）**

- バリアントごとに「原寸の頭サイズ」を定数で持つ（`HEAD_UNIT_PX`）。1期生 78.1px / 2期生 108.0px / live2d 75.0px
  - 1期生の 78.1px は「瞳の中心→顎の下端」の実測平均。**2期生は同じ測り方だと 94.0px だが、この値では揃わない**。2期生KVは目が大きく描かれていて瞳の中心が顎に近いため、「瞳→顎」を合わせると頭全体は1期生の約1.15倍になる。1期生と並べて頭のシルエットが揃う 108.0px を採用している
  - つまり U は「顔の一部の長さ」ではなく**頭全体の大きさの基準**。絵柄が変われば測り直しが必要
- `U = min(基準値, (談話室の高さ - テーブル高) / 頭上マージン)`。画面が縦に狭いときだけ全員一律に縮小され、3体の相対関係は崩れない
- 画像の表示幅 = `原寸幅 / HEAD_UNIT_PX × U × 個体補正`。これにより**全タレントの頭が同じ大きさで表示される**
  - 画像高さではなく**幅**で指定する。2期生KVは画像高さが個体ごとに異なり（見かけの身長にほぼ比例）、高さ基準では「背が高いキャラほど小さく描画される」逆転が起きるため
- **個体補正**（`HEAD_SCALE_MAP`、未設定は 1.0）: バリアント基準だけでは揃わない個体差を吸収する。とくに1期生KVは低身長のタレントほど頭が大きく描かれており、そのままでは「背が低いほど頭が大きい」ように見えてしまう
  - **縮尺の決定に身長は使わない**。身長は縦位置にのみ反映する
  - 個体補正は**画像の拡縮にだけ効かせ、顎の目標高さには掛けない**。倍率をいじっても背の高さは変わらない（画像内の顎位置 `chinY` は画像と一緒に伸縮するので、その分だけ計算に入れる）

**縦位置（顎の位置で合わせる）**

- 画像上端ではなく**顎の位置**を基準に配置する。頭頂は髪型・帽子で変動するため揃わない
- タレントごとの顎のy座標（原寸px）は `CHIN_Y_PX` に実測値を持つ
- 顎の高さ = テーブル上端 + `(基準オフセット + 身長オフセット) × U`
- 身長オフセット = `(身長 - 基準身長) / 顔1つ分の実寸換算(cm) × 身長反映率`
  - 身長反映率 1.0 で実寸比例。実際にはKV立ち絵が全員ほぼ同じ画角で描かれており、そのまま比例させると低身長タレントがテーブルに沈むため 0.6 を既定とする
- ポーズ（足を上げる・開脚など）で見かけの身長が変わっても、足元ではなく顎を基準にするため影響を受けない

#### KV未提供タレントの立ち絵

- KV立ち絵が未提供のタレント（現在は冬星れんこん 26WA003 のみ）は、live2d立ち絵（`live2d/orig/*.webp`、バストアップ）で代替表示する
- バリアント `live2d` として同じ計算式に載せる（判定は `usesLive2dImages()`）

#### 実測値のメンテナンス

- KV画像を差し替えたら、そのタレントの顎y座標を測り直して `kvMetrics.ts` を更新する（原寸y座標を目視で読む）
- 新しい絵柄のバリアントが増えたら `HEAD_UNIT_PX` を決める。既存バリアントと並べて**頭のシルエットが揃う値**を探すこと。顔の一部の寸法（瞳→顎など）を合わせるだけでは揃わない
- デバッグ画面（`/debug` → KV立ち絵スケール）に全タレントを並べて確認できる
  - 世代（1期生 / 2期生 / 全員）× 並び順（ID順 / 身長順 / ランダム）を切り替えられる。**全員 × ランダム**は世代混在の見え方を確かめる用途。「ランダム」は押すたびに引き直す
  - 個体補正のスライダーで調整し、「倍率TSコピー」で `HEAD_SCALE_MAP` に貼る
  - 横長のPCで開いても談話室の比率を再現するため、縦長の仮想ビューポート（19.5:9）を内部で組み立てている

### 4. 吹き出し

- タレントがランダムなタイミングでセリフを表示する（ゲーム画面のアシスタントとは独立）
- 表示中のタレントの中からランダムに1体を選び、その頭上付近に吹き出しを表示
- 一度に表示される吹き出しは**1つまで**

#### 表示タイミング

- 一定間隔（例：15〜30秒ごと）でランダムに出現
- 数秒間表示した後フェードアウト
- ユーザー操作（スロットタップ等）中は出現しない

#### セリフのソース

クイズ画面のアシスタントセリフとは**完全に独立**。クイズの進行に関するリアクションではなく、談話室でくつろいでいるタレントの日常的なつぶやきを表現する。

##### コンセプト

タレントたちが談話室のテーブルを囲んで雑談している雰囲気。テーブルの上のおやつ・飲み物への感想、日常の独り言、趣味の話など、ゲーム画面とは無関係な内容。

##### セリフカテゴリ

| カテゴリ | 内容例 | 備考 |
|---------|--------|------|
| おやつ・飲み物 | 「このクッキーおいしい」「紅茶あったかい〜」 | テーブルに食べ物がある設定 |
| 日常のつぶやき | 「今日もいい天気だね」「ちょっと眠い…」 | 時間帯や季節に非依存の汎用的なもの |
| 趣味・好きなもの | 「最近○○にハマってて」「○○楽しいよね」 | プロフィールの趣味・好物を反映 |
| 他タレントへの言及 | 「○○ちゃん元気かな」 | 同寮・仲良しタレントへの言及 |
| プレイヤーへの声かけ | 「クイズ楽しんでる？」「また遊びにきてね」 | 控えめに混ぜる |

##### データ構造

アシスタントセリフと同じ仕組み（口調グループ + タレント固有）で管理する。

```json
{
  "groups": {
    "丁寧語": ["このクッキーおいしいですね", "今日も穏やかですね", ...],
    "ギャル": ["このお菓子まじうま〜", "ねむ〜い", ...],
    ...
  },
  "talents": {
    "犬丸なでこ": ["おやつおいしいわん🐾", ...],
    ...
  }
}
```

- 口調グループごとに汎用セリフを用意（各10〜15パターン程度）
- タレント固有セリフはプロフィール・趣味・口癖を活かしたものを任意で追加
- タレント固有セリフは口調グループの汎用セリフとマージされ、ランダム選択される（アシスタントと同じ方式）
- セリフ上限は全角16文字以内（アシスタントと同じ）
- `{player}` プレースホルダー使用可

##### スプレッドシート管理

既存のセリフシートで `場面: 談話室` として管理する。sync-spreadsheet.ts の既存ロジックでそのまま取り込まれ、quotes.json 内にアシスタントセリフと同じ構造で格納される。

| 口調タイプ | 場面 | セリフ1 | セリフ2 | … |
|-----------|------|--------|--------|---|
| 丁寧語 | 談話室 | このクッキーおいしいですね | 今日も穏やかですね | … |
| 犬丸なでこ | 談話室 | おやつおいしいわん🐾 | … | |

#### 配置

- x方向: 立ち絵のx方向中心 = 吹き出しのx方向中心
- y方向: 立ち絵画像の上から1/3の位置 = 吹き出しのy方向中心。ただし吹き出しが画面外にはみ出す場合はクランプして画面内に収める
- 吹き出しの尻尾は常に上向き（発言タレントの立ち絵の上に重なる形）

#### 演出

- 吹き出しはテーブルより手前（最前面）に表示
- フェードイン・フェードアウトで自然に出現・消失

### 5. 選択UI（スロットタップ方式）

#### 基本操作

1. **空きスロットをタップ** → タレント選択ドロップダウンが開く
2. **立ち絵をタップ** → 同じドロップダウンが開く（タレント変更 or 解除）
3. **ドロップダウンで「解除」を選択** → スロットが空になる

#### 空きスロットの表示

- 薄い円形 or 枠線で「＋」マークを表示（タップ可能であることを示す）
- 背景に溶け込むよう半透明

#### ドロップダウン

- 前作踏襲の寮別グループ化リスト
- 寮名ヘッダー → タレント一覧（各寮内）
- 先頭に「解除」選択肢を追加
- 他のスロットで選択済みのタレントはグレーアウト（同一タレントの重複配置を防止）
- 1期生・2期生の両方を表示（世代でサブグループ化するかは要検討）

#### タレント選択ボタンの表示タイミング

- **タイトル画面のとき**のみ選択UIを表示（`showSelector` prop、前作踏襲）
- クイズ中・結果画面等では立ち絵のみ表示、選択操作は不可

## データ永続化

- LocalStorage に選択状態を保存
- キー：`parermaster2_room`
- 値：`{ left: string | null, center: string | null, right: string | null, dormitory: string }`（タレントIDまたはnull、寮名）
- 初回アクセス時：中央スロットにランダムな1期生を配置、左右は空、背景の寮はランダム

## 実装方針

### コンポーネント構成

```
RoomArea（メインコンテナ）
├── 背景画像
├── TalentSlot × 3（左・中央・右）
│   ├── 立ち絵画像 + GSAPアニメーション
│   └── 空きスロット表示（＋マーク）
├── テーブル画像（立ち絵の手前）
├── SpeechBubble（吹き出し、テーブルの手前）
└── TalentSelector（ドロップダウン、1つだけ表示）
```

### ファイル配置

- `src/features/room/` ディレクトリに配置
  - `RoomArea.tsx` — メインコンテナ
  - `TalentSlot.tsx` — 立ち絵スロット（アニメーション含む）
  - `TalentSelector.tsx` — ドロップダウン選択UI（画面下部ボトムシート形式）
  - `useRoomStore.ts` — Zustand ストア（スロット選択状態 + LocalStorage永続化）
  - `SpeechBubble.tsx` — 吹き出し表示

### 配置場所

`src/app/App.tsx` で GameContainer の直後に配置。`useScreenMode()` フックで 2:3 以下のときのみ表示：

```tsx
const screenMode = useScreenMode()
const showRoom = screenMode === 'portrait-room'
// ...
{showRoom && <RoomArea showSelector={screen === 'title'} />}
```

## 前作との差分

| 項目 | 前作 | 今作 |
|------|------|------|
| 立ち絵数 | 1体 | 最大3体 |
| 選択方法 | 右上ドロップダウン1つ | スロットタップ → ドロップダウン |
| 「談話室のみ」モード | あり（寮ごと） | なし（スロットを全て解除すれば背景のみ） |
| 背景の決定 | 選択タレントの寮 | 中央→左→右の優先順で寮決定 |
| 2期生対応 | なし（1期生のみ） | あり（KV未提供タレントのみlive2d立ち絵で代替） |
| テーブル | なし | 手前にテーブルを配置、立ち絵の下半身を自然に隠す |
| 吹き出し | なし | タレントがランダムにセリフを表示（セリフ内容は保留） |
| データ保存 | タレントID 1つ | 3スロット分のオブジェクト |
